# SCPRec core implementation

This repository contains the core implementation accompanying the SCPRec
paper. It provides the model wrappers, prompt conversion, LoRA setup, rollout
generation, privileged distillation trainer, dynamic item bank, online
four-expert scoring, checkpointing, and evaluation protocol needed to inspect
the proposed method. It is not presented as a standalone end-to-end
reproduction package.

Only release-specific changes were made:

- machine-local paths were replaced with environment variables;
- internal legacy identifiers were mechanically renamed;
- comments and documentation were converted to English;
- checkpoints, logs, and external baseline repositories were not redistributed.

No precomputed item embedding matrix or precomputed expert score matrix is
used by the training path in this repository.

## Runtime

The principal package version constraints are listed in `requirements.txt`. Install the
matching CUDA build of PyTorch 2.5.1 first, then install the remaining
requirements. The source combination uses Transformers 4.48.2, Accelerate
1.6.0, PEFT 0.15.0, TRL 0.16.1, vLLM 0.7.3, and DeepSpeed 0.15.4.

The default backbone is `Qwen/Qwen2.5-3B-Instruct`. Set
`MODEL_NAME_OR_PATH` to a local Hugging Face model directory when the training
machine is offline.

## Dataset

Training reads processed Hugging Face `DatasetDict` directories saved with
`save_to_disk`. Place the released datasets under `data/`. Each dataset must
contain `train`, `valid`, `test`, and `item_info` splits. Dataset preprocessing
programs are intentionally outside this core-code release.

## Train the four experts

```bash
DATASET_DIR=data/Amazon_Books_UserSample25K \
CHECKPOINT_DIR=checkpoints/amazon_books_experts \
DEVICE=cuda:0 \
bash scripts/train_experts.sh
```

This produces the four checkpoints consumed online by Stage II. Every expert
fits on 90% of the original `train` rows and uses the same seeded 10% subset
for early stopping and validation-NDCG routing quality. The official `valid`
and `test` splits remain untouched for reporting. Expert scores are computed
from each current history/user batch during Stage II.

## Stage I

```bash
CUDA_VISIBLE_DEVICES=0,1,2,3,4 \
NUM_PROCESSES=4 \
MODEL_NAME_OR_PATH=/path/to/Qwen2.5-3B-Instruct \
DATASET_CAT=Amazon_Books \
DATASET_DIR=data/Amazon_Books_UserSample25K \
OUTPUT_DIR=checkpoints \
RUN_NAME=amazon-books-stage1 \
NUM_TRAIN_EPOCHS=2 \
MAX_NEW_TOKENS=256 \
bash scripts/launch_stage1.sh
```

With vLLM enabled, the last visible GPU is reserved for rollout generation and
`NUM_PROCESSES` counts the training processes.

## Stage II

```bash
CUDA_VISIBLE_DEVICES=0,1,2,3,4 \
NUM_PROCESSES=4 \
MODEL_NAME_OR_PATH=/path/to/Qwen2.5-3B-Instruct \
DATASET_CAT=Amazon_Books \
DATASET_DIR=data/Amazon_Books_UserSample25K \
STUDENT_CHECKPOINT=checkpoints/amazon-books-stage1/final_checkpoint \
TEACHER_CHECKPOINT=checkpoints/amazon-books-stage1/final_checkpoint \
SASREC_CHECKPOINT=checkpoints/amazon_books_experts/sasrec.pt \
LIGHTGCN_CHECKPOINT=checkpoints/amazon_books_experts/lightgcn.pt \
SMALL_MOE_FMLPREC_CHECKPOINT=checkpoints/amazon_books_experts/fmlprec.pt \
SMALL_MOE_EASE_CHECKPOINT=checkpoints/amazon_books_experts/ease.pt \
OUTPUT_DIR=checkpoints \
RUN_NAME=amazon-books-stage2 \
MAX_NEW_TOKENS=256 \
bash scripts/launch_stage2.sh
```

Stage II loads the Stage-I LoRA adapter as both student initialization and the
default frozen privileged teacher. The launcher uses the paper configuration:

- token distillation weight `1.0`;
- soft entropy-gap weighting with threshold `0.0`, temperature `0.1`, and
  minimum teacher top-K mass `0.8`; positions below that mass receive zero
  distillation weight;
- target InfoNCE weight `0.1`;
- four-expert soft-mixture weight `0.1` with target-rank improvement;
- full item-bank refresh every eight optimizer steps;
- inactive auxiliary objectives fixed to zero.

The student item bank is generated by the current LLM from the item prompts.
A frozen teacher receives its own isolated item-bank snapshot. SASRec,
LightGCN, FMLP-Rec, and EASE are loaded from checkpoints and score each batch
online.

Both stage launchers enable fixed-epoch combined evaluation. The runtime
concatenates the original `valid` and `test` rows into one `test` split,
regenerates unique interaction IDs, and reports `eval_test_*` over this merged
set. Ranking uses the eligible full catalog after excluding padding and items
already present in the visible history.
